I've been building web applications for **5 years**. I run my own platform end-to-end — **10 apps sharing 10 internal packages** — covering my portfolio, agency site, admin panel, CMS, and API. Every client project is built the same way, on the same foundation. Here's exactly how.

## The proof: my own platform

Instead of telling you my code is clean, here's what I actually operate: **one codebase powering 10 applications** — this site, my agency site, an internal admin panel, a self-hosted CMS, an API, and a ready-to-deploy client template — built on **10 shared packages** for authentication, UI, database, email, and payments.

When your project starts, it starts on this foundation — not from zero. That's why the first version ships in weeks, not months.

Everything is built from **small, reusable components** on a fully type-safe stack (**Next.js, TypeScript, tRPC**). In plain terms: bugs get caught before your users ever see them, and changes stay fast and safe as the product grows.

## How I use AI

I use AI every single day, and I'm specific about how — because "AI-assisted" can mean anything.

**My daily driver is Claude Code**, running the latest Claude models (currently **Fable 5** and **Opus**). But the tool isn't the point — the workflow is:

1. **I decide the architecture first.** Before any code is written, I plan the approach and approve it.
2. **AI implements my decisions** — and writes the tests and boilerplate, the repetitive 60% of the work.
3. **I read every change before it ships.** Tests confirm the behavior; I confirm the design.

I've also built my own AI setup: custom commands, per-project convention files, and persistent memory — so the AI works to my standards, not its defaults.

What this means for you: **the speed of AI with the judgment of a senior developer.** "Isn't AI code sloppy?" It is — when nobody's steering. Steering is my job.
